1

Kubernetes Auth Method 활성화

Vault에서 kubernetes 인증 방식 활성화

Vault에 Kubernetes 인증 메커니즘을 활성화합니다.

vault auth enable kubernetes
결과

Kubernetes Auth Method가 kubernetes/ 경로에 활성화됨

이 명령은 Vault가 ServiceAccount의 JWT 토큰을 검증할 수 있게 합니다.
2

K8s 클러스터 정보 등록

Vault가 K8s API 서버와 통신하기 위한 설정

Kubernetes 클러스터 정보를 Vault에 등록합니다.

vault write auth/kubernetes/config \ kubernetes_host="https://192.168.137.10:6443" \ kubernetes_ca_cert="-----BEGIN CERTIFICATE----- ...(K8s CA 인증서)... -----END CERTIFICATE-----" \ token_reviewer_jwt="eyJhbGciOiJSUzI1NiIsImtpZCI6...(ServiceAccount JWT)..."

등록된 정보

항목값
API Serverhttps://192.168.137.10:6443
CA CertificateKubernetes 클러스터 CA 인증서
Token Reviewerdefault ServiceAccount Token
결과

Vault가 K8s API 서버와 안전하게 통신할 수 있도록 설정 완료

Token Reviewer JWT는 Vault가 Pod의 ServiceAccount 토큰을 검증할 때 사용됩니다.
3

정책(Policy) 생성

Pod이 접근 가능한 권한 정의

app-policy 정책을 생성하여 Pod의 권한을 정의합니다.

vault policy write app-policy - << 'EOF' # Allow reading KV v2 secrets in the app path path "secret/data/app/*" { capabilities = ["read", "list"] } # Allow reading metadata path "secret/metadata/app/*" { capabilities = ["read", "list"] } EOF

정책 권한

경로허용된 동작
secret/data/app/*read, list
secret/metadata/app/*read, list
결과

app-policy가 생성되어 secret/app/* 경로의 모든 시크릿을 읽을 수 있습니다.

이 정책은 읽기만 허용하며, 쓰기는 허용하지 않습니다 (최소 권한 원칙).
4

Kubernetes Role 생성

ServiceAccount와 정책을 연결하는 역할 정의

app-role Kubernetes role을 생성하여 정책과 ServiceAccount를 연결합니다.

vault write auth/kubernetes/role/app-role \ bound_service_account_names=default \ bound_service_account_namespaces=default \ policies=app-policy

역할 설정

항목값
Role Nameapp-role
ServiceAccountdefault
Namespacedefault
Policiesapp-policy
결과

default namespace의 default ServiceAccount를 가진 Pod이 Vault에 인증할 수 있게 되었습니다.

bound_service_account_names과 bound_service_account_namespaces는 이 role을 사용할 수 있는 Pod을 제한합니다.

설정 완료 체크리스트

  • Kubernetes Auth Method 활성화 (kubernetes/)
  • K8s 클러스터 정보 등록 (API Server, CA, Token)
  • app-policy 정책 생성 (secret/app/* 읽기 권한)
  • app-role Kubernetes Role 생성
  • default namespace의 default ServiceAccount와 바인딩 완료

인증 흐름 요약

Pod (default SA, default 네임스페이스)
↓
ServiceAccount JWT 토큰 전달
↓
Vault가 K8s API로 토큰 검증
↓
app-role 매칭 (SA + 네임스페이스 확인)
↓
app-policy 부여
↓
Vault Token 발급 → secret/app/* 읽기 가능
