HashiCorp Vault 설치 계획

Ubuntu 24.04 APT 직접 설치 (Master 노드)

대상 서버
master
192.168.137.10
OS
Ubuntu 24.04.4 LTS
설치 방식
APT Repository
저장소
Integrated Raft

⚠️ 보안 주의사항

Unseal Key와 Root Token은 절대로 문서나 공유 장소에 저장하지 않습니다.

초기화 후 발급되는 Unseal Key(5개) 3개와 Root Token은 반드시 안전한 곳(예: 패스워드 매니저, 오프라인 저장소)에 별도로 보관하세요. 이 계획 문서에는 더미 값만 표시하며, 실제 설치 시 발급된 값을 즉시 기록하고 보호하셔야 합니다.

1

사전 준비

설치 대상 확인 및 필요한 포트 열기

다음 정보를 확인합니다:

  • SSH 접속: master 노드에 SSH로 접속 가능
  • 권한: sudo 권한 필요
  • 포트: 8200 (API/UI), 8201 (Cluster) 개방 필요
  • 디스크: /opt 경로에 최소 5GB 여유 공간
💡 현재 master 노드는 192.168.137.10에 Ubuntu 24.04.4 LTS가 실행 중입니다.
2

HashiCorp GPG 키 및 저장소 등록

APT 저장소에서 Vault를 설치하기 위한 준비

HashiCorp의 공식 APT 저장소를 등록합니다.

wget -O- https://apt.releases.hashicorp.com/gpg | gpg --dearmor | sudo tee /usr/share/keyrings/hashicorp-archive-keyring.gpg

저장소 리스트 추가:

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list

패키지 인덱스 업데이트:

sudo apt update
3

Vault 패키지 설치

APT를 통한 vault 바이너리 및 관련 파일 설치

sudo apt install -y vault

설치 후 버전 확인:

vault version
💡 APT 설치 시 vault 사용자, 그룹, systemd 서비스가 자동으로 생성됩니다.
4

데이터 디렉토리 생성 및 권한 설정

Vault가 저장소 데이터를 보관할 디렉토리 준비

Raft 저장소용 디렉토리를 생성합니다:

sudo mkdir -p /opt/vault/data sudo chown -R vault:vault /opt/vault/data sudo chmod 700 /opt/vault/data
💡 /opt/vault/data는 Vault의 상태, Raft 로그, 시크릿 등이 저장되는 중요한 디렉토리입니다.
5

Vault 설정 파일 작성

/etc/vault.d/vault.hcl 설정

기본 vault.hcl 파일을 생성합니다 (TLS는 나중에 추가 가능):

sudo tee /etc/vault.d/vault.hcl > /dev/null <

설정 파일 권한:

sudo chmod 644 /etc/vault.d/vault.hcl
💡 tls_disable = 1은 랩 환경 및 내부 테스트용입니다. 프로덕션 환경에서는 반드시 TLS를 활성화하세요.
6

Vault 서비스 활성화 및 시작

systemd 서비스를 통해 Vault 실행

systemd 서비스를 활성화하고 시작합니다:

sudo systemctl enable vault sudo systemctl start vault

서비스 상태 확인:

sudo systemctl status vault

로그 확인:

sudo journalctl -u vault -f
💡 "Vault server started! Log data will stream in below:" 메시지가 보이면 정상 시작된 것입니다.
7

Vault 초기화 (Operator Init)

Unseal Key와 Root Token 생성

환경 변수를 설정한 후 초기화를 진행합니다:

export VAULT_ADDR='http://127.0.0.1:8200' vault operator init -key-shares=5 -key-threshold=3

예상 출력:

Unseal Key 1: xxxxxxxxxxxxxxxxxxxxxxxxxx Unseal Key 2: xxxxxxxxxxxxxxxxxxxxxxxxxx Unseal Key 3: xxxxxxxxxxxxxxxxxxxxxxxxxx Unseal Key 4: xxxxxxxxxxxxxxxxxxxxxxxxxx Unseal Key 5: xxxxxxxxxxxxxxxxxxxxxxxxxx Initial Root Token: s.xxxxxxxxxxxxxxxx

🔐 중요: Unseal Key와 Root Token 저장

위 출력 결과를 즉시 안전한 위치에 저장하세요:

  • Unseal Key 5개 중 3개가 필요합니다 (threshold)
  • Root Token은 초기 관리용입니다
  • 절대로 공개 저장소나 이메일로 전송하지 마세요
  • 비트와든(Bitwarden) 같은 보안 패스워드 매니저 사용 권장
8

Vault Unseal

저장된 Unseal Key로 Vault를 Unseal 상태로 변경

3개의 Unseal Key를 사용하여 Vault를 언씰합니다 (3회 실행):

export VAULT_ADDR='http://127.0.0.1:8200' vault operator unseal # 각 실행 시마다 Unseal Key를 입력합니다. # 예시 입력 값: # Unseal Key (will be hidden): [여기에 첫 번째 키 입력]

3번 반복 실행 후 상태 확인:

vault status

예상 출력:

Key Value --- ----- Seal Type shamir Initialized true Sealed false Total Shares 5 Threshold 3 ... Cluster Name vault-cluster-xxx Version 1.x.x
💡 "Sealed: false"가 표시되면 언씰 완료입니다.
9

Vault 정상 동작 확인

API 및 UI를 통한 동작 확인

터미널에서 Root Token으로 로그인하여 상태를 확인합니다:

export VAULT_ADDR='http://127.0.0.1:8200' export VAULT_TOKEN='s.xxxxxxxxxxxxxxxx' # 위에서 발급받은 Root Token vault status vault auth list vault secrets list

웹 UI 접속:

http://192.168.137.10:8200/ui

UI 로그인:

  • Token: 위의 Root Token 입력
  • Sign in 클릭
💡 UI에서 Secrets, Auth Methods, Audit 탭 등을 확인할 수 있습니다.

다음 단계 (선택사항)

  • Audit Log 활성화: 모든 Vault 작업을 로깅하기 위해 audit backend 설정
  • KV v2 Secrets Engine: 시크릿 저장소 활성화 (기본값으로 많이 사용)
  • TLS 인증서 설정: 프로덕션 배포 시 자체 서명 또는 내부 CA 인증서로 tls_disable 비활성화
  • Kubernetes 연동: k8s 클러스터에서 Vault 인증 메커니즘 설정 (Kubernetes Auth Method)
  • Backup 및 Disaster Recovery: Raft snapshot을 통한 정기적인 백업 자동화
  • 권한 관리 (RBAC): 역할 기반 접근 제어로 Root Token 외 별도 정책 설정

이 계획은 Ubuntu 24.04 환경에서의 HashiCorp Vault 기본 설치를 가이드합니다.

자세한 정보는 Vault 공식 문서를 참고하세요.
